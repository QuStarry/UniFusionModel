# 大模型兼容融合小模型：研究方向可行性深度调研报告

## 一、核心结论

**你的想法具有很高的研究价值和可行性，但需要聚焦。** "大模型兼容融合小模型"并非一个空白领域——过去三年，模型合并（Model Merging）、知识蒸馏、MoE、模型拼接（Stitching）、工具调用（Tool Use）、动态路由六条技术路线都从不同侧面探索了这个问题。然而，**现有工作普遍只解决了"兼容、直接使用、深度融合、经验互鉴"四个维度中的1-2个，缺乏一个统一框架同时覆盖全部四个维度**。这正是你的核心创新空间所在。

具体判断如下：

1. **参数级融合已较成熟但受同架构限制**：Task Arithmetic（Ilharco等，2022）、TIES-Merging、LM-Cocktail（Xiao等，2023）等方法能零训练合并多个同尺寸模型，但无法直接合并不同规模/架构的大小模型，且合并是静态的，无法动态选择。

2. **调用级融合（Tool Use/Routing）已工业化但缺乏"内化"**：Toolformer（Schick等，2023）、ToolOrchestra（Su等，2025）、HierROUTER（Gupta等，2025）让大模型能动态调用小模型，但小模型始终是"外部工具"，其能力没有真正内化到大模型中，输入输出需要格式转换。

3. **双向知识流动刚刚起步**：CTCD（Lee等，2023）首次证明小模型知识反向蒸馏能增强大模型，CrossLM（Deng等，2023）、Single-Multi Evolution Loop（Feng等，2026）进一步探索了协同进化，但大多停留在训练阶段，推理时动态双向流动尚未解决。

4. **最有潜力的创新点**：构建一个**"统一兼容融合框架"**，同时实现：①异构模型的即插即用兼容；②外部调用与内部融合的双模式切换；③推理时双向知识流动；④融合后的能力协同增强。这四条单独看都有前驱工作，但**统一在一起是空白**。

## 三、六大技术路线研究现状

### 3.1 参数空间融合（Model Merging）

**核心思想**：直接在权重空间合并多个模型，无需额外训练。

**代表性工作**：
- **Task Arithmetic**（Ilharco等，2022）：提出"任务向量"概念，通过权重加减实现多任务能力组合，是该方向的奠基性工作。
- **LM-Cocktail**（Xiao等，2023）：通过加权平均合并微调模型与基座模型，缓解微调后的通用能力退化。
- **TIES-Merging / DARE**：通过重置、剪枝、合并三步减少参数干扰，成为当前最常用的合并方法。
- **Sens-Merging**（Liu等，2025）：基于参数敏感度动态调整合并系数，在Mistral 7B和LLaMA2上显著提升代码和数学能力。
- **Twin-Merging**（Lu等，2024，NeurIPS）：将知识模块化分解为共享/专属组件，动态合并，在20个数据集上平均提升28.34%。
- **FS-Merge**（Kinderman等，2024）：用超网优化解决不同初始化模型的合并问题，数据效率高。
- **Model Merging in Pre-training**（ByteDance Seed，2025）：首次系统研究预训练阶段的模型合并，在100B+参数MoE上验证有效性。

**核心局限**：
- 几乎所有方法要求模型**架构完全相同**（同层数、同隐藏维度、同tokenizer），无法直接合并7B大模型和1B小模型。
- 合并是**静态一次性**的，合并后无法动态选择使用哪个子模型的能力。
- 合并后各模型的**专业能力会相互干扰**（负迁移），虽有Twin-Merging等缓解方案，但未根本解决。

### 3.2 模型拼接与嫁接（Model Stitching/Grafting）

**核心思想**：在模型中间层引入轻量"缝合层"（stitch layer），连接不同模型的部分模块。

**代表性工作**：
- **BTS (Branch-Train-Stitch)**（Zhang等，2025，Meta）：从一个seed模型分支训练多个领域专家，再用stitch层将专家表征整合回seed模型。专家可随时增删，是最接近你想法的工作之一。
- **SN-Net (Stitchable Neural Networks)**（Pan等，2023）：在同家族不同尺寸模型间拼接，实现精度-效率的动态权衡。
- **KLAS**（Sanyal等，2026）：用中间表征的KL散度自动选择最优拼接点，ImageNet上提升1.21%或减1.33× FLOPs。
- **Bridging Large Gaps**（Traft & Cheney，2024）：实现跨架构拼接（ResNet低层→Swin高层），但需复杂适配器。

**核心局限**：
- BTS要求所有专家从**同一seed模型分支训练**，无法直接使用"已有的、独立训练的"小模型——这恰恰是你想法的关键场景。
- stitch层增加推理开销，且拼接位置选择仍是启发式的。
- 跨架构/跨规模拼接效果显著下降。

### 3.3 大模型编排调用小模型（Tool Use / Routing）

**核心思想**：大模型作为控制器，根据输入动态选择调用合适的小模型/工具。

**代表性工作**：
- **Toolformer**（Schick等，2023，Meta）：让模型自学习何时调用API、传什么参数，是工具调用的奠基工作。
- **ToolOrchestra**（Su等，2025，NVIDIA）：训练8B小编排器协调多种工具和模型，在HLE基准上37.1%超过GPT-5的35.1%，且效率高2.5倍。
- **GEAR**（Lu等，2024）：将工具grounding交给小模型、执行交给大模型，实现大小模型分工。
- **HierROUTER**（Gupta等，2025）：用强化学习训练分层路由，动态组装多模型推理流水线，质量提升2.4×。
- **Cascade Routing**（Dekoninck等，2024，ICML）：统一路由与级联，证明质量估计器是关键。
- **EquiRouter**（Lai & Ye，2026）：发现"路由坍缩"问题（预算增加后路由器总是选最贵模型），提出直接学习模型排序的解决方案。

**核心局限**：
- 小模型始终是**外部工具**，其能力没有内化到大模型的参数中。
- 调用开销大（多次前向传播），且输入输出需要序列化/反序列化。
- 路由器本身需要训练数据，且存在"路由坍缩"等失效模式。

### 3.4 知识蒸馏与双向学习（Knowledge Distillation）

**核心思想**：通过软标签/中间表征，在大小模型间传递知识。

**代表性工作**：
- **CTCD (Co-Training and Co-Distillation)**（Lee等，2023）：**关键突破**——首次证明小模型→大模型的反向蒸馏能提升大模型性能，且增强后的大模型进一步提升小模型，形成正循环。小模型最终超过独立训练的大模型1.66分（GLUE）。
- **CrossLM**（Deng等，2023，清华）：跨孤岛知识迁移，小模型用私有数据训练后促进大模型生成高质量数据，双方同时增强。
- **LEMON**（Chen等，2024，ACL）：通过线性参数融合从大模型"复活"小模型，支持任意尺寸和架构转换。
- **MCKD**（Zhao等，2024，ACL）：多阶段协同蒸馏，学生模型迭代产生更好的伪标签。
- **Single-Multi Evolution Loop**（Feng等，2026）：多模型协作→蒸馏到单模型→再协作的进化闭环，单模型平均提升8.0%，协作系统提升14.9%。
- **Learning to Seek Help**（Zeng等，2026）：小模型学习何时向大模型求助，大模型提供自适应反馈。

**核心局限**：
- 双向蒸馏大多发生在**训练阶段**，推理时的动态知识流动尚未解决。
- 蒸馏需要大量无标签数据和多轮训练，成本高。
- 蒸馏后小模型的独特专业能力可能被大模型的"平均化"稀释。

### 3.5 专家混合（Mixture of Experts, MoE）

**核心思想**：将模型拆分为多个专家子网络，通过路由器动态选择激活。

**代表性工作**：
- **ModuleFormer**（Shen等，2023）：从无标注数据中自发涌现模块化，支持新模块即插即用扩展。
- **Upcycling LLMs into MoE**（He等，2024，NVIDIA）：将已训练的密集模型升级为MoE，Nemotron-15B升级后MMLU从65.3%→67.6%。
- **Nexus**（Gritsch等，2024）：支持用独立训练的密集模型作为新专家扩展MoE，新增专家仅需少量微调。
- **Dynamic MoE**（Huang等，2024，ACL）：根据输入难度动态调整激活专家数量。

**核心局限**：
- 传统MoE的专家需要**联合训练**，无法直接使用已有的独立小模型。
- Nexus等upcycling方法虽支持独立专家，但要求同架构，且路由器需要重新训练。
- 专家间的知识共享和协同仍是开放问题。

### 3.6 表征对齐与跨模型迁移（Representation Alignment）

**核心思想**：在隐空间建立不同模型间的映射，实现表征级知识迁移。

**代表性工作**：
- **SemAlign**（Gu等，2026，ACL Findings）：提出"潜在语义对齐"是跨尺度知识迁移的前提，用激活值而非参数作为迁移媒介，实现跨架构迁移。
- **LRT Hypothesis**（Bello等，2025）：提出线性表征可迁移性假设——不同规模模型的表征空间间存在仿射变换，小模型学到的steering vector可迁移到大模型。
- **Parameter-efficient transfer from small to large**（Jin等，2023，EMNLP）：利用大小模型PEFT模块的相似性，将小模型的适配器迁移到大模型，内存减少5.7×。

**核心局限**：
- 表征对齐主要用于**行为引导**（steering），尚未用于完整的能力融合。
- 对齐质量随模型规模差距增大而下降。
- 缺乏理论保证，对齐映射的可解释性不足。

## 四、研究空白与创新机会

### 4.1 四维覆盖矩阵

| 技术路线 | 输入输出兼容 | 直接使用 | 深度融合 | 经验互鉴 |
|---------|------------|---------|---------|---------|
| 模型合并 | ❌ 需同架构 | ❌ 静态不可分 | ✅ 参数级 | ❌ 无流动 |
| 模型拼接 | ⚠️ 需stitch层 | ⚠️ 半动态 | ✅ 中间层 | ❌ 无双向 |
| 编排调用 | ✅ API/序列化 | ✅ 动态路由 | ❌ 外部调用 | ❌ 无内化 |
| 知识蒸馏 | ✅ 软标签对齐 | ❌ 训练阶段 | ⚠️ 知识迁移 | ⚠️ 多为单向 |
| MoE | ⚠️ 需联合训练 | ✅ 动态路由 | ✅ 模块化 | ❌ 专家独立 |
| 表征对齐 | ✅ 空间映射 | ⚠️ 推理引导 | ⚠️ 隐式融合 | ⚠️ 单向为主 |

**关键发现：没有任何一条路线同时覆盖四个维度。**

### 4.2 五个具体研究空白

**空白1：异构模型的"即插即用"兼容层**
现有方法要么要求同架构（合并/MoE），要么需要针对每对模型单独训练对齐层（拼接/表征对齐）。缺乏一个**通用的模型适配层**，能让任意架构、任意规模、任意模态的小模型通过标准化接口接入大模型。

**空白2：外部调用与内部融合的统一机制**
Tool Use和Model Merging被视为两条独立路线。但实际场景中，**低频/新任务适合外部调用，高频/核心任务适合内化融合**。缺乏能在两者间动态切换的统一机制——调用多次后自动"内化"，内化后也可"卸载"回调用模式。

**空白3：推理时双向知识流动**
CTCD等证明了训练时双向蒸馏有效，但推理时大模型如何**动态吸收**小模型的专业经验（而不是重新训练）？小模型又如何从大模型的推理过程中**实时学习**？这是一个几乎未被探索的方向。

**空白4：融合后的能力涌现与协同**
现有研究主要关注"能力保持"（合并后不退化），很少研究融合是否产生**1+1>2的协同效应**。例如，代码小模型+数学小模型融合后，是否在"用代码解数学题"这类交叉任务上超过任一单模型？

**空白5：融合过程的可解释性与可控性**
模型合并是"黑箱操作"，用户无法知道合并后哪些能力来自哪个子模型，也无法精确控制各子模型能力的权重。缺乏**可解释、可精确调控**的融合机制。

## 五、三个候选研究方向对比

基于以上分析，我提炼出三个有实质差异的研究方向：

### 方向一：UniFusion — 面向异构模型的统一兼容融合框架

**一句话核心问题**：如何设计统一的兼容接口与双模式融合机制，让任意专业小模型能即插即用地接入大模型，并在"外部调用"与"内化融合"间动态切换？

**技术路线**：
1. **模型适配层（Model Adapter）**：基于SemAlign的潜在语义对齐思想，设计一个轻量通用适配层，将任意小模型的输入输出映射到大模型的表征空间。用小模型的少量校准数据（few-shot）训练适配层。
2. **双模式融合引擎**：
   - 调用模式：大模型通过router决定是否调用小模型，类似Tool Use但走统一表征接口而非文本序列化。
   - 融合模式：对高频调用的小模型，通过LoRA式参数注入将其能力"内化"到大模型的特定层。
3. **自适应模式切换**：基于调用频率、延迟预算、任务相似度，自动决定何时从调用升级为融合，何时从融合降级为调用。
4. **双向知识流动模块**：融合模式下，小模型的专业表征持续正则化大模型的对应层；大模型的通用表征也通过适配层反馈优化小模型。

**创新点**：
- 首次统一"调用"与"融合"两种范式
- 异构模型即插即用，突破同架构限制
- 自适应模式切换，兼顾效率与能力

**可行性**：★★★★☆（高）
- 适配层有SemAlign、BTS stitch层的技术基础
- 双模式切换有MoE动态路由的参考
- 实验可在LLaMA2-7B（大）+ 多个1-3B专业小模型上验证

**发表潜力**：★★★★★（很高）
- 统一框架类工作容易发NeurIPS/ICML/ACL
- 工业应用价值大，容易引起关注
- 国内《计算机学报》《软件学报》也欢迎系统性框架工作

**风险**：
- 适配层的泛化性可能不足，不同小模型可能需要不同配置
- 双模式切换的决策逻辑需要精心设计

---

### 方向二：SymbioLLM — 大小模型共生进化的双向知识流动框架

**一句话核心问题**：如何构建大小模型间的推理时双向知识流动闭环，让通用能力与专业能力相互增强、持续进化？

**技术路线**：
1. **能力互补分工机制**：基于任务难度估计器，大模型负责复杂推理/泛化，小模型负责专业领域/模式匹配。
2. **推理时双向蒸馏**：
   - 大→小：大模型的推理链（CoT）作为软标签，在线更新小模型的轻量适配器。
   - 小→大：小模型的专业输出作为"外部记忆"，通过注意力偏置或特征注入影响大模型的下一轮推理。
3. **进化闭环**：协作产出的高质量样本定期用于双方的增量训练，形成"协作→蒸馏→进化→再协作"的循环。
4. **能力评估与分工动态调整**：持续监控大小模型在各子任务上的表现，动态调整分工边界。

**创新点**：
- 推理时双向知识流动（区别于CTCD的训练时双向蒸馏）
- 共生进化的闭环机制
- 能力互补的动态分工

**可行性**：★★★☆☆（中高）
- 训练时双向蒸馏已有CTCD、CrossLM验证
- 推理时在线更新适配器有参数高效微调的基础
- 但推理时训练的稳定性和效率是挑战

**发表潜力**：★★★★☆（高）
- "共生/进化"概念新颖，理论意义强
- 适合ICLR/NeurIPS的learning方向
- 国内期刊看重理论深度

**风险**：
- 推理时在线学习可能导致不稳定
- 进化闭环的收敛性需要理论保证
- 实验周期可能较长

---

### 方向三：CrossGraft — 跨规模模型的参数空间嫁接与能力移植

**一句话核心问题**：如何突破同架构限制，将小模型的专业能力作为"功能模块"直接参数级移植到大模型中？

**技术路线**：
1. **跨规模参数对齐**：基于GIT Re-Basin的置换对称思想，结合LRT假设的线性映射，在小模型和大模型的对应层间建立参数级对应关系。
2. **模块化嫁接**：将小模型的特定层（如专业领域的FFN层）作为"器官"，通过维度变换层移植到大模型的对应位置，与大模型原有层并行或替换。
3. **免疫适应训练**：用少量数据训练嫁接层的门控机制，防止"排异反应"（性能退化），促进嫁接模块与原生模块的协同。
4. **可插拔管理**：嫁接模块可随时激活/禁用/替换，支持多专业模块的组合。

**创新点**：
- 跨规模参数级嫁接（区别于同架构的模型合并）
- 模块化能力移植，可精确控制
- 免疫适应机制

**可行性**：★★★☆☆（中）
- 参数对齐有GIT Re-Basin、LRT假设的基础
- 但跨规模（如1B→7B）的参数对应关系尚未被充分验证
- 嫁接位置和方式需要大量实验探索

**发表潜力**：★★★★☆（高）
- 技术难度大但创新性强
- 适合NeurIPS/ICML的模型架构方向
- "器官移植"隐喻容易引起关注

**风险**：
- 跨规模参数对齐可能效果不佳，表征相似性不等于参数可交换性
- 嫁接后的训练可能仍然成本较高
- 与方向一的适配层有一定重叠

## 一、维度补充：从四维到八维

你原来的四个维度抓住了核心，但在实际落地中还有四个同等重要的维度被遗漏了。完整的八维框架如下：

| 维度 | 核心问题 | 为什么重要 |
|------|---------|-----------|
| **① 兼容性** | 异构模型的输入输出能否对齐？ | 不同架构/规模/模态的模型无法直接对接 |
| **② 直接使用** | 大模型能否动态调用小模型？ | 决定了新模型能否即插即用 |
| **③ 深度融合** | 小模型能力能否内化到大模型？ | 决定了推理效率和能力深度 |
| **④ 经验互鉴** | 大小模型能否双向增强？ | 决定了系统是否持续进化 |
| **⑤ 可解释与可控** | 融合后能力从何而来？能否精确调控？ | 出问题时无法定位，无法按需调节各专业权重 |
| **⑥ 效率与资源** | 融合后的延迟、显存、吞吐如何？ | 同时加载多个模型成本极高，实际部署不可接受 |
| **⑦ 安全与隔离** | 小模型的错误/偏见会不会污染大模型？能否回滚？ | 专业模型可能有领域偏见或幻觉，融合后可能"感染"大模型 |
| **⑧ 防遗忘** | 融合新能力会不会导致大模型原有能力退化？ | 多任务融合中的灾难性遗忘是经典难题 |

**关键洞察**：现有六条技术路线（合并/拼接/调用/蒸馏/MoE/对齐）没有任何一条同时覆盖八维。UniFusion的目标就是成为第一个八维全覆盖的框架。

### 2.1 已验证的"专业模型优势"领域

## 三、UniFusion 技术架构设计

### 3.1 核心洞察：从"文本级调用"到"隐状态级融合"

现有Tool Use的根本问题是**文本序列化瓶颈**：大模型生成文本→调用小模型→小模型返回文本→大模型解析文本。这个过程信息损失大、延迟高、无法深度融合。

UniFusion的核心创新是**在隐状态空间（hidden state space）做模型间的调用与融合**，把小模型当作大模型的一个"可插拔计算层"。

### 3.2 三层架构总览

```
┌─────────────────────────────────────────────────────────┐
│                   大模型基座 (Qwen2-7B)                   │
│                                                         │
│  Layer 1 ──► Layer 2 ──► ... ──► Layer k ──► ... ──► Layer N │
│                              │                          │
│                    ┌───────┴───────┐                    │
│                    │  融合决策点    │                    │
│                    │  (Fusion Gate)│                    │
│                    └───────┬───────┘                    │
│                            │                            │
├────────────────────────────┼────────────────────────────┤
│           统一适配与路由层 (Adaptation & Routing)         │
│                            │                            │
│  ┌──────────┐  ┌────────┐  │  ┌────────┐  ┌──────────┐ │
│  │ 能力注册表 │  │ 路由器  │  │  │ 适配层  │  │ 门控融合  │ │
│  │Capability│  │ Router │  │  │ Adapter│  │  Gating  │ │
│  └──────────┘  └────────┘  │  └────────┘  └──────────┘ │
├────────────────────────────┼────────────────────────────┤
│                            │                            │
│  ┌─────────┐  ┌─────────┐  │  ┌─────────┐  ┌─────────┐ │
│  │代码专家  │  │数学专家  │  │  │医学专家  │  │  ...    │ │
│  │Coder-6.7B│  │Math-7B │  │  │Med-7B  │  │         │ │
│  └─────────┘  └─────────┘  │  └─────────┘  └─────────┘ │
│         专业小模型池 (Specialist Pool)                    │
└─────────────────────────────────────────────────────────┘
```

### 3.3 第一层：能力注册表与发现（Capability Registry）

**解决问题**：大模型怎么知道哪个小模型擅长什么？

**设计**：
- 每个小模型接入时附带一个**能力卡（Capability Card）**，包含：
  - 擅长任务类型（代码生成/数学推理/医学问答...）
  - 输入输出格式规范
  - 在标准基准上的性能画像
  - 置信度范围和已知失败模式
- 大模型维护一个**动态能力注册表**，不仅记录静态能力卡，还通过实际调用持续更新每个小模型的真实表现
- 能力发现机制：对新接入的小模型，自动运行一组探测任务（probe tasks），快速建立能力画像

**创新点**：这不是静态的工具描述（如OpenAPI），而是**动态更新的能力指纹**，路由器基于真实表现而非描述做决策。

### 3.4 第二层：统一适配层（Unified Adapter）

**解决问题**：不同架构/规模的小模型如何对接？

**设计**：适配层是一个轻量神经网络，为每个小模型学习一对投影矩阵：

```
大模型隐状态 h_large (d_large) 
    │
    ▼ 投影矩阵 P_in (d_large → d_small)
小模型输入 h_small (d_small)
    │
    ▼ 小模型前向传播
小模型输出 h'_small (d_small)
    │
    ▼ 投影矩阵 P_out (d_small → d_large)
增强后的隐状态 h'_large (d_large)
```

**关键技术细节**：
1. **层间对齐**：不是任意层都能对接。基于SemAlign（Gu等，2026）的层归因方法，自动找到大模型和小模型之间语义最匹配的层对。例如，代码模型的第20层可能对应大模型的第16层。
2. **少样本校准**：每个小模型只需50-100条领域样本训练适配层（8卡H800上几分钟完成），不需要重新训练小模型。
3. **异构支持**：即使小模型和大模型层数不同、隐藏维度不同，投影矩阵都能处理。极端情况下（如小模型是CNN/RNN），适配层还包含一个序列对齐模块。

**与BTS的区别**：BTS要求所有专家从同一seed模型分支训练，UniFusion的适配层支持**任意已训练的独立模型**，这是核心差异。

### 3.5 第三层：双模式融合引擎（Dual-Mode Fusion）

这是UniFusion最核心的创新。两种模式不是二选一，而是**渐进过渡**的两个阶段。

#### 模式A：调用模式（Call Mode）—— 隐状态级工具调用

**工作流程**：
1. 大模型正常前向传播到第k层
2. 路由器判断：当前输入是否需要某个专业小模型？
3. 如果需要，将第k层隐状态通过适配层传入小模型
4. 小模型完成前向传播，输出增强隐状态
5. 门控融合层学习如何混合：`h_out = g * h_small_enhanced + (1-g) * h_large_native`
6. 大模型继续后续层的推理

**优点**：
- 零训练（适配层一次性校准后即可用）
- 可热插拔，新小模型随时接入
- 能力可追溯——输出中哪些部分来自小模型可量化
- 小模型错误可隔离——门控g可以设为0来完全屏蔽

**缺点**：
- 推理时多一次小模型前向传播，延迟增加约30-50%
- 显存中需要同时保留大模型和被调用的小模型

**适用场景**：新接入的小模型、低频任务、需要可解释性的场景

#### 模式B：融合模式（Fuse Mode）—— 渐进式能力内化

**核心思想**：当某个小模型被高频调用时，将其能力"蒸馏"成大模型的一个LoRA适配器，然后卸载小模型。

**渐进式内化四阶段算法**：

```
阶段1: 纯调用 (Call-only)
  ├─ 收集调用日志：(输入, 大模型原生输出, 小模型增强输出)
  └─ 统计调用频率和性能增益

阶段2: 预热蒸馏 (Warm-up Distillation)
  ├─ 用调用日志训练一个LoRA适配器
  ├─ 训练目标：让LoRA的输出逼近小模型增强后的隐状态
  ├─ 损失函数：MSE(h_lora, h_small_enhanced) + KL(p_lora, p_small)
  └─ 此时仍以调用模式为主，LoRA只做辅助

阶段3: 融合切换 (Fuse Switch)
  ├─ 当LoRA在验证集上达到小模型性能的95%时
  ├─ 逐步将门控从"调用小模型"过渡到"激活LoRA"
  ├─ 过渡期间两者混合，平滑切换
  └─ 切换完成后，小模型可从显存卸载

阶段4: 协同进化 (Co-evolution)
  ├─ 融合后的大模型在专业数据上继续轻量微调
  ├─ 目标：超越原小模型（因为有大模型的通用推理能力加持）
  └─ 微调后的LoRA可导出，作为新的"专业能力模块"分享
```

**关键创新——能力正交化（Capability Orthogonalization）**：

当融合多个专业LoRA时，它们的参数可能相互干扰。UniFusion用梯度投影实现能力正交：

```
对于新加入的专业能力i：
  1. 计算已有能力的参数子空间 S = span{θ_1, θ_2, ..., θ_{i-1}}
  2. 将新能力的梯度投影到S的正交补空间：g' = g - proj_S(g)
  3. 这样新能力只在"未被占用"的参数方向上更新
  4. 同时用EWC正则化保护大模型通用能力
```

**实验预期**：融合3个专业能力后，每个专业领域的性能下降不超过1%，通用能力（MMLU）下降不超过0.5%。

#### 模式切换决策器

```
切换 Call → Fuse 的条件：
  ✓ 该小模型调用频率 > 阈值（如30%的请求触发）
  ✓ 调用后性能增益稳定（方差小）
  ✓ LoRA预热达到性能阈值
  ✓ 显存/延迟预算紧张

切换 Fuse → Call 的条件（回滚）：
  ✗ 融合后该领域性能持续下降
  ✗ 需要更新小模型到新版本
  ✗ 该领域调用频率骤降
```

### 3.6 第四维创新：推理时双向知识流动

传统双向蒸馏（如CTCD）只在训练时发生。UniFusion实现**推理时的实时双向流动**：

**大→小（上下文增强）**：
- 调用小模型时，不仅传入当前token的隐状态，还传入大模型的"推理上下文"——包括已生成的CoT摘要、相关的内部知识检索结果
- 这相当于给小模型提供了"大模型视角的问题理解"，帮助小模型在复杂上下文中更好地发挥专业能力
- 实现方式：适配层的输入包含 [当前隐状态; 上下文向量]，上下文向量来自大模型的注意力池化

**小→大（知识注入）**：
- 小模型的输出不仅用于当前位置的隐状态增强，还写入大模型的**KV Cache的特定槽位**
- 这相当于小模型给大模型注入了"专业记忆"，影响后续所有token的生成
- 例如，医学小模型识别出"患者有糖尿病史"，这个信息被注入KV Cache后，大模型后续所有推理都会考虑这个因素

**这不是训练，是推理时的实时知识交换**——这是UniFusion区别于所有现有工作的关键创新点。
